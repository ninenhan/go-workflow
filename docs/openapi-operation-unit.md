# OpenAPI Operation Unit

`OpenAPIOperationUnit` executes one operation generated by the Web editor's strict
OpenAPI importer. Service authors import an OpenAPI 3.0 or 3.1 JSON document once;
ordinary workflow users receive selectable actions and generated run-form fields
without editing JSON.

## Supported contract

- Absolute HTTP(S) server URL without credentials, query, fragment, or variables.
- `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, and `DELETE`.
- Primitive path, query, and header parameters.
- `application/json` request bodies whose schema contains primitive fields or
  unambiguous nested objects up to eight levels deep. Nested leaves become
  hierarchical run-form questions and are rebuilt at their original JSON paths.
- Flat `multipart/form-data` request bodies containing primitive fields and
  OpenAPI `string`/`binary` file fields. Files are selected when the workflow
  runs and are never persisted as fixed service configuration.
- Object `allOf` composition at the request root or inside nested objects.
  Properties and required fields are merged before questions are generated.
- Flat arrays of string, number, or integer body values. They become add, remove,
  and reorder list controls; numeric items are converted back to JSON numbers.
- Primitive arrays with item enums become multi-select controls. Boolean arrays
  require enum choices so ordinary users never need to type boolean literals.
- String `minLength`/`maxLength`, numeric inclusive or exclusive
  `minimum`/`maximum`, and array `minItems`/`maxItems`. The generated form shows
  the limits before submission and blocks invalid values; the runtime validates
  the same normalized contract before any network request.
- Primitive enums are carried into the runtime as allowed values, including enum
  items inside multi-select arrays, so callers cannot bypass the generated choices.
- OpenAPI 3.0 `nullable: true` and OpenAPI 3.1 value types combined with `null`.
  The generated form uses an explicit "Send no value" switch so JSON `null`
  remains distinct from an omitted optional property.
- Object `oneOf` choices at the request root or inside an ordinary object.
  The form presents a required variant choice and reveals only that branch's
  questions; the runtime validates and builds only the selected branch.
- `oneOf` discriminators whose choices are local schema references. Every branch
  must require the discriminator as a string; when a branch uses `const` or
  `enum`, that constraint must accept its mapped value. The branch selector writes
  the value to the declared JSON path, so users choose the branch once instead of
  entering a duplicate type field.
- No authentication, Bearer, Basic, or one header/query API key security scheme.
- Automatic, JSON, or text response parsing through the shared `HttpUnit` runtime.

Unsupported operations are rejected explicitly by the importer. It does not silently
drop nested multipart objects, nullable files, constrained array items, regex patterns,
`multipleOf`, free-form boolean arrays, object arrays, conflicting object compositions,
external references, unresolved server variables, composite security alternatives,
recursive schemas, `oneOf` nested inside another conditional variant, optional objects
with conditionally required children, ambiguous discriminator mappings, or unsupported
parameter/body shapes.

## Runtime safety

The runtime validates the imported contract again before every request. It rejects
relative or credential-bearing server URLs, path traversal segments, unresolved path
parameters, invalid or reserved header names, header line breaks, duplicate argument
keys, conflicting or oversized body paths, invalid primitive body values, request
bodies on `GET` or `HEAD`, and unsupported methods or content types. Array values
must be actual lists and are validated item by item, including count and enum limits.
Text length uses Unicode characters rather than encoded byte length. Optional
booleans remain absent until the user explicitly chooses Yes or No. Discriminator
values are accepted only from the imported variant group and cannot overlap an
ordinary body field path.

Multipart values use a strict inline file descriptor validated at both the generated
operation boundary and the shared HTTP runtime. Each file is limited to 4 MiB, all
files in one request to 8 MiB, each scalar part to 1 MiB, and the encoded multipart
body to 12 MiB. The run creation endpoint limits its JSON payload to 16 MiB. File
names must be safe basenames; MIME types, strict base64 data, declared sizes, field
counts, and descriptor keys are validated before any network request is sent.

Credentials should use named environment variables. Their values are resolved by the
existing credential subsystem and are not stored in workflow definitions, portable
packages, browser persistence, or API responses.

The source OpenAPI JSON or YAML remains a developer-facing import artifact. Only the
selected, normalized operation contracts are installed as reusable service actions.
